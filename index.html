Real-time voice agents

Under 700 ms per turn at p95+

Phone and website agents had to answer fast, cope with people talking over them, and keep working when a provider went down.

  • Built the LiveKit pipeline with automatic fallback across 20+ LLMs and 20+ speech providers.
  • Replaced a timer-based speech-to-text setup with a parallel adapter that races providers and keeps the first result.
  • Made interruption handling configurable, including resuming after a false interruption. Wrote custom speech plugins.

LiveKit, Twilio SIP, WebRTC, Kafka, Kubernetes on GKE and AKS, Python

Evals that block bad releases

Production incidents fell from 3–4 a day to 3–4 a week+

Prompt and model changes kept breaking voice and chat agents after release. I made every release pass automated evals first.

  • Langfuse with LLM-as-judge on every release, over simulated conversations and red-team cases.
  • Live A/B tests of agent variants in outreach campaigns, picked by conversion rate.

Langfuse, LLM-as-judge, OpenTelemetry

One gateway for every LLM call

Six integrations replaced, 3–5 ms added per call+

Six services each talked to LLM providers their own way. I proposed one stateless gateway and built it: model routing, prompt caching and tool calls over gRPC, with zero-downtime deploys.

Sending simple steps to cheaper models, and to plain rules where no model was needed, was a large part of cutting cost per message and per call by 10 to 20 times.

Python, gRPC, Gemini explicit caching, Redis

A form-filling assistant with a 64% smaller prompt

Form filling went from 30 minutes to 6+

A router sends each message to one of several specialised agents. The form-filling agent was carrying more than 50,000 tokens a request across 80+ branching questions.

18K tokens
  • Moved form state out of the prompt into its own service. The model writes answers through one function call: a JSON path and a value.
  • Pruned the prompt every turn and replaced LangChain with direct OpenAI calls.
  • Built a search agent that samples the data, then writes, runs and fixes its own SQL.

Azure OpenAI, Django, function calling, structured outputs

Agents on top of an undocumented enterprise API

An MCP server with 30 tools over hundreds of endpoints+

The API had hundreds of undocumented endpoints. I mapped them into 30 tools agents can use safely, and built scheduled AI briefings on top.

I also built a Graph-RAG memory service in Neo4j with chunking and reranking, and wrote testing and observability templates that three other teams adopted.

Python MCP SDK, FastMCP, Azure AI Foundry, Neo4j, Langfuse

I was the first developer and built most of the product: voice, SMS, WhatsApp and email campaigns run as Temporal workflows. A rules-based dialer, regex voicemail detection and a cached opening greeting took the LLM out of steps that didn't need it.
